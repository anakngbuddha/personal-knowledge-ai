Implements `Project_Plan.md` **Phase 3 (Grounded Answers)**: cited, grounded AI answers that refuse when the context is insufficient.

## 1. Overview of Phase 3 Deliverables

Phase 3 builds the orchestration layer between Phase 2's permission-aware retrieval and the user interface. It ensures that every response generated by the system is strictly grounded in retrieved evidence, properly cited with provenance indicators, protected against prompt injection, and subject to hard cost controls.

## 2. Architectural Components

### A. LLM Provider Layer (`app/llm/`)
- **`base.py`**: Abstract `LLMProvider` defining synchronous (`generate_grounded_answer`) and streaming (`stream_grounded_answer`) interfaces. Returns structured `GroundedAnswer` and `GroundedAnswerChunk` objects.
- **`gemini.py`**: Concrete provider for Gemini models using `httpx` directly. Supports single-turn generation and streaming SSE. No external SDK bloat.
- **`fake.py`**: Deterministic provider for hermetic testing and offline evaluation. Cites retrieved chunks and declines when context is empty.
- **`factory.py`**: LRU-cached provider resolution based on `settings.llm_provider` (`gemini` vs `fake`).
- **`prompts.py`**: Versioned prompts (`PROMPT_VERSION = "3.0.0"`). Embeds `SYSTEM_CONTRACT`, source formatting with freshness flags, and instructions strictly forbidding speculation, competitive claims, or ungrounded pricing.

### B. Generation & RAG Orchestration (`app/generation/`)
- **`service.py`**:
  1. Checks per-user rate limit (`check_rate_limit`).
  2. Checks per-org monthly token budget (`check_token_budget`).
  3. Executes permission-aware hybrid search (`app.retrieval.search.search`).
  4. Wraps each hit in untrusted fences (`wrap_untrusted`).
  5. Formats context with citation anchors and metadata.
  6. Invokes LLM provider.
  7. Tracks token usage (`record_token_usage`) and persists messages.
- **`conversations.py`**: CRUD operations on `Conversation` and `Message` tables, including message turn history truncation and workspace-level tenant isolation.
- **`rate_limit.py`**: In-memory sliding window rate limiter (requests per minute) and PostgreSQL-backed monthly token budgets.
- **`schemas.py`**: Pydantic models for request validation (`AskIn`, `AskFiltersIn`) and output serialization (`AskOut`, `MessageOut`, `ConversationOut`, `StreamChunkOut`).

### C. API Endpoints (`app/api/routes/ask.py`)
- `POST /ask`: Generate grounded answer (sync or SSE streaming).
- `POST /conversations`: Create conversation thread.
- `GET /conversations`: Paginated list of conversations.
- `GET /conversations/{id}`: Fetch conversation details with messages and sources.
- `DELETE /conversations/{id}`: Delete conversation and message history.
- `POST /conversations/{id}/ask`: Continue multi-turn conversation with previous context.
- `GET /conversations/{id}/sources`: Inspect source collateral for a conversation.

## 3. Intentional Changes & Design Decisions

1. **Direct `httpx` HTTP Client over Google GenAI SDK**:
   Following the pattern established for embeddings in Phase 2, `app/llm/gemini.py` communicates directly via the Gemini REST API (`generateContent` and `streamGenerateContent`). This avoids heavy SDK dependencies and ensures full control over connection pools, timeouts, and SSE parsing.

2. **In-Memory Sliding Window for Per-User Rate Limiting**:
   Per-user rate limiting uses a thread-safe sliding window counter. For initial team deployment (~50 users), this avoids an external Redis dependency while strictly mitigating rapid-fire query abuse. When scaling to multi-replica deployments, the interface easily drops in a Redis token bucket.

3. **Monthly Per-Org Token Budgets**:
   Budgets are tracked in the database (`token_budgets` table) partitioned by calendar month (`month = YYYY-MM-01`). If an org reaches its prompt or completion limit, queries are blocked with `HTTP 429 TokenBudgetExhausted`.

4. **Source Toggling (`exclude_document_ids`)**:
   `AskIn` supports explicit document exclusion. The RAG orchestration filters these documents out prior to context construction, allowing users to toggle untrusted or irrelevant collateral off directly in the UI.

## 4. Honest Gaps & Future Work

- **Hand-Scored Golden Benchmark**: A 50-question evaluation dataset with expert ground-truth annotations remains to be curated alongside field SE teams during Phase 4.
- **Distributed Rate Limiting**: As noted, sliding window rate limits are currently in-memory per process. Production clustering requires migrating to Redis or PostgreSQL advisory locks.
- **Model Fallback Cascade**: If the primary Gemini model encounters API rate limits or downtime, automated failover to an alternative model or region is not yet configured.
